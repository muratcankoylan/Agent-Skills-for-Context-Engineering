# Sourcing harness: measured local results

Date: September 7, 2026. Status: supervised local implementation; production activation remains disabled. No commit, push, merge, accepted skill promotion or cloud deployment was performed. This report concerns research content, not personal contact enrichment.

The [research/design report](report-source.md) records the primary literature, alternatives, interfaces and semantic evaluation protocol. This report separates actual external observations from deterministic verification and remaining hypotheses.

## What changed

- arXiv has explicit relevance/recency/facet lanes, query-bound cursors, versioned work identity, distinct published/updated dates, categories, DOI and primary links. The campaign entry point adds shared daily query reservations, request spacing and immutable cached observations.
- Company research now includes bounded official DeepMind, Hugging Face and Microsoft Research feed windows. Inline content, XML Base, truncation and source scope are preserved. These windows are not topical search results or independent corroboration.
- X parsing retains enriched long-form text, outbound URL entities and referenced-post provenance. Existing default wire behavior is preserved. Enriched requests remain live-unvalidated because official field-name documentation conflicts; campaign X queries are staged, not executed.
- A supervised primary reader produces inert HTML text with capture hashes, reader identity and extracted-text spans. Fetch targets must be discovered first and pass an additional fixed host/path/DNS policy. No JavaScript, automatic link crawling or PDF fallback is enabled.
- Compact discovery packets deduplicate provenance references, preserve original selected text and reconstruct the full occurrence index. Default v1 output remains compatible; the example brief explicitly selects v2.

The relevance and newest arXiv sets were disjoint in this small sample. That establishes different candidate coverage, not better recall. The broader follow-up returned an agent-memory lead alongside hardware-memory and spin-glass papers. Query broadening needs facet-level relevance evaluation; greater yield alone is not success.

The parser now tolerates duplicate attributes it does not consume. Duplicate URL, visibility and encoding attributes still fail closed. Re-extraction creates a separate artifact bound to the original result and capture; it does not overwrite history. Both retained pages were re-extracted with DNS and HTTP forbidden. Neither page's scientific claims were independently verified. The Microsoft page remains a company blog, not a paper; zero extracted-text omissions does not prove full-paper completeness.

## Context packing experiment

Input: the same frozen 56-work campaign. Selection remains lane-round-robin, not semantic ranking. All provenance was retained; selected text was identical to its original record.

| Packet budget | v1 selected works | Compact v2 selected works | Actual v2 bytes |
| --- | ---: | ---: | ---: |
| 64 KiB | 2 | 15 | 65,288 |
| 128 KiB | 29 | 42 | 130,801 |
| 256 KiB | 56 | 56 | 189,526 |

The full v1 packet occupied 214,203 bytes. Compact v2 reduced that to 189,526 bytes without dropping a work, changing selected text or losing reconstructable provenance. At smaller budgets it makes more complete work records available instead of spending the budget on repeated metadata.

Repeated whole-packet serialization was replaced with exact incremental byte accounting. Three compact builds per budget took 36.018–37.164 ms on this local input; the earlier implementation's recorded single builds took approximately 1.12–1.41 seconds. This is a finite local packing measurement, not a production latency SLO or a semantic-quality result. Original v1 packet hashes and expanded v2 provenance were checked for equality against retained real observations.

## Verification

The final full Python suite ran **1,000 tests in 170.054 seconds: OK**. Tests include query/cursor binding, source metadata, untrusted URLs, packet bounds, source failures, tampering, cache reuse, missing artifacts, rollback of the clock, primary-reader failures and offline re-extraction. No product-pipeline model or paid-API call was made.

Final source checks passed: strict repository validation, reference platform compatibility, generated inventory consistency and Ruff on the affected modules/tests. Platform validation covered 17 skills and four local layouts. Inventory covered 338 artifacts and 306 declared input snapshots. Activation fixtures also passed. The Stage 0 command passed three checks but executed **zero benchmark scenarios**; it is not semantic-effectiveness evidence.

Secret scanning covers present tracked and non-ignored untracked publication candidates, not private runtime captures, the Git index or historical revisions. Ignored Python bytecode contains synthetic private-key-header test fixtures; those are not publication candidates. The private scan receipt records exactly which files were scanned and any already-missing tracked files. Existing unrelated changes were not staged or repaired by this work.

## Remaining release gates

1. **Semantic effectiveness:** freeze a multi-question candidate pool and obtain independent blinded facet judgments. Compare query variants at matched request and review budgets; group uncertainty estimates by underlying information need. This run does not establish retrieval precision, recall or downstream skill improvement.
2. **X wire contract and cost:** resolve the documented dialect conflict, accept the adapter contract, provision the credential securely and run a resource-budgeted canary. Parsed fixtures do not prove live access, billing or pagination behavior.
3. **Primary coverage:** measure supported HTML coverage and failure rate before deciding whether a larger response budget or isolated PDF reader is justified. Do not silently widen budgets when a paper fails.
4. **Operations:** the shared campaign gate coordinates one cache on this machine, not every caller or host. The existing Codex heartbeat is supervised follow-up, not OS cron or an always-running product agent. Production scheduling, semantic evaluation and accepted skill promotion remain separate gates.

The next useful experiment is the matched-budget, blinded relevance study, not more unattended query variants. Research findings remain candidate evidence until a reviewer establishes mechanism relevance and claim support.
